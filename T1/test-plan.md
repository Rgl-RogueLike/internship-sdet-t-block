# Задача T1. Написание тест-кейсов

## 1. Описание тестируемой функциональности

Тестируется REST API `GET /products/{productId}/status`, предназначенный для получения статуса продукта по его идентификатору. Метод принимает обязательный параметр `productId`, параметр авторизации `authToken` и необязательные query-параметры `recalculate`, `owner` и `region`.

В случае успешного выполнения запроса сервис возвращает HTTP-код `200` и JSON-объект с полем `productStatus`. При возникновении ошибок сервис возвращает соответствующие HTTP-коды и тело ответа согласно требованиям.

## 2. Анализ требований

### Входные параметры

| Параметр | Тип | Обязательный | Допустимые значения |
|-----------|-----|--------------|---------------------|
| productId | Path | Да | Идентификатор продукта |
| authToken | Query | Да | Строка из 16 буквенно-цифровых символов |
| recalculate | Query | Нет | true, false, null |
| owner | Query | Нет | Создатель, Пользователь, null |
| region | Query | Нет | Северо-Запад, Сибирь, Поволжье |

### Возможные ответы сервиса

| HTTP-код | Описание |
|-----------|----------|
| 200 | Статус продукта успешно получен |
| 401 | Неверный или отсутствующий authToken |
| 404 | Продукт не найден |
| 500 | Внутренняя ошибка сервера |

## 3. План тестирования

В рамках тестирования необходимо проверить следующие аспекты работы REST API:

1. **Проверка авторизации**
    - запрос с валидным `authToken`;
    - запрос с отсутствующим `authToken`;
    - запрос с невалидным `authToken`.

2. **Проверка параметра `productId`**
    - получение статуса существующего продукта;
    - запрос несуществующего продукта.

3. **Проверка параметра `recalculate`**
    - передача допустимых значений (`true`, `false`, `null`);
    - отсутствие параметра;
    - передача невалидного значения.

4. **Проверка параметра `owner`**
    - передача допустимых значений (`Создатель`, `Пользователь`, `null`);
    - отсутствие параметра;
    - передача невалидного параметра

5. **Проверка параметра `region`**
    - передача допустимых значений (`Северо-Запад`,`Сибирь`, `Поволжье`);
    - отсутствие параметра;
    - передача невалидного значения.

6. **Проверка успешного ответа**
    - HTTP-код `200`;
    - соответствие структуры JSON требованиям;
    - корректность значения `productStatus`.

7. **Проверка обработки ошибок**
    - возврат HTTP-кода `401` при отсутствии или неверном токене;
    - возврат HTTP-кода `404` при отсутствии продукта;
    - возврат HTTP-кода `500` при ошибке обработки запроса с телом ответа в формате JSON, содержащим поле `errorMessage`, согласно требованиям.

### Применяемые техники тест-дизайна

При составлении тест-кейсов используются следующие техники-тест дизайна:

- **Классы эквивалентности** – для проверки:
    - допустимых и недопустимых значений входных параметров;
    - обязательных и необязательных параметров запроса. 
- **Анализ граничных значений** – для проверки ограничений длины `authToken`.
- **Негативное тестирование** – для проверки обработки невалидных входных данных и ошибочных сценариев.
